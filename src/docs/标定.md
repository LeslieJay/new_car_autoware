可以把到达日志做成“误差标定表”，核心不是直接平均 dx/dy，而是先转换到目标点坐标系中的纵向、横向误差，再根据不同目标朝向判断误差来源。

  设日志定义为：

  dx = current_x - goal_x
  dy = current_y - goal_y
  yaw_error = current_yaw - goal_yaw

  转换公式：

  longitudinal =  cos(goal_yaw) * dx + sin(goal_yaw) * dy
  lateral      = -sin(goal_yaw) * dx + cos(goal_yaw) * dy
  yaw_error    = normalize(current_yaw - goal_yaw)

  其中：

  - longitudinal > 0：车辆越过目标点。
  - longitudinal < 0：车辆提前停。
  - lateral > 0：车辆停在目标朝向的左侧。
  - lateral < 0：车辆停在目标朝向的右侧。

  ## 1. 先筛选有效停车样本

  不要把“刚触发到达的单帧”直接用于标定。建议只接受：

  |speed| < 0.03 m/s
  连续稳定时间 >= 2 s
  停车段内位置 RMS < 0.01 m
  停车段内 yaw RMS < 0.2°

  最终位姿使用停车后最后 1～2 秒的平均值。

  每个目标点建议：

  - 同方向重复至少 10 次。
  - 正向、反向都测试。
  - 至少选择 4 种明显不同的目标朝向。
  - 尽量从相同距离、相同速度接近。
  - 同时保存目标位姿、最终定位、trajectory 终点和控制停车点。

  ## 2. 纵向误差标定

  统计每个终点的纵向误差：

  longitudinal_mean = mean(longitudinal_error)
  longitudinal_std  = std(longitudinal_error)

  判断方式：

  - 所有朝向都稳定提前相近距离：停车控制或规划 stop margin 偏大。
  - 所有朝向都稳定超调：减速度不足、控制延迟或车辆参考点配置不准。
  - 正向和反向误差符号相反：很可能是 base_link、前后轴或车辆外形参考点配置错误。
  - 误差随接近速度增大：制动响应延迟或减速度模型问题。
  - trajectory 终点本身偏离 goal：规划问题。
  - trajectory 终点正确但车辆偏离：控制跟踪问题。

  可以拟合：

  longitudinal_error =
      static_offset
    + response_delay * approach_speed
    + deceleration_scale * approach_speed²

  其中：

  - static_offset 用于修正固定停车偏差。
  - 与速度一次项相关，通常代表执行延迟。
  - 与速度平方相关，通常代表制动距离模型。

  不要仅凭一次测试直接修改 stop_margin。这次三个点的纵向误差分别约：

  +3.38 cm
  +4.51 cm
  -2.72 cm

  平均约 +1.72 cm，目前看纵向固定偏差不大，不建议做大幅补偿。

  ## 3. 横向误差标定

  本次横向误差分别约：

  -20.69 cm
  -13.68 cm
  -3.24 cm

  明显比纵向问题严重，而且都偏同一侧。

  需要判断它属于哪一种固定偏差。

  ### 目标坐标系偏差

  如果不同目标朝向下，lateral_error 始终近似相同，例如始终为负，则更可能是：

  - 避障路径横移没有完全回正。
  - 终点轨迹相对 goal 有横向偏置。
  - 控制器存在稳定横向跟踪误差。
  - 车辆中心线或 base_link 横向位置配置错误。

  ### 地图坐标系偏差

  如果原始 dx/dy 在地图坐标系中近似固定，但转换后的纵横向误差随目标朝向变化，则更可能是：

  - 地图与定位坐标系存在平移误差。
  - NDT 地图配准有整体偏置。
  - goal 数据和定位数据使用了不同地图基准。

  可用多目标点做最小二乘估计：

  [dx_i]   [ cos(yaw_i)  -sin(yaw_i)] [longitudinal_bias]
  [dy_i] = [ sin(yaw_i)   cos(yaw_i)] [lateral_bias     ]

  利用所有停车样本拟合统一的：

  longitudinal_bias
  lateral_bias

  如果拟合残差很小，说明车辆坐标系中确实存在固定偏移，可以进一步检查 base_link 和轨迹偏置；如果残差很大，则不是单一静态标定量。

  ## 4. 航向误差标定

  先计算环绕后的航向误差：

  yaw_error = atan2(sin(current_yaw-goal_yaw),
                    cos(current_yaw-goal_yaw))

  判断方式：

  - 所有目标朝向的 yaw error 都接近同一个值：定位航向、IMU 安装角或 base_link 航向存在固定偏置。
  - yaw error 随转向方向改变符号：转向控制、方向盘零位或车辆运动学参数问题。
  - 直线目标准确，弯道终点误差大：终点前直线段太短或控制器没有足够距离回正。
  - yaw error 大时横向误差同步增大：很可能是航向未对正导致车辆沿错误方向进入终点。

  本次航向误差为：

  +6.54°
  +2.29°
  +5.28°

  三次都为正，存在固定正向航向偏差的嫌疑，但样本只有三个，还不能直接把约 +4.7° 当成 IMU 标定量。需要用正反方向重复实验验证：

  - 如果反向行驶后仍然是约 +4～5°：检查定位航向/IMU 安装角。
  - 如果反向后误差变成负值：检查转向控制和终点轨迹。

  ## 5. speed 如何参与分析

  建议到达日志额外记录：

  speed_at_arrival
  approach_speed_1s
  approach_speed_2s
  longitudinal_acceleration
  steering_angle
  trajectory_end_x/y/yaw
  control_stop_point_x/y

  speed_at_arrival 主要用于确认车辆是否真正稳定：

  - speed > 0.05 m/s：不能作为最终停车标定样本。
  - speed 接近 0，但仍缓慢变化：应等待稳定窗口。
  - 误差与 approach_speed 高度相关：优先标定制动模型。
  - 不同速度下误差基本固定：优先检查静态参考点和 stop margin。

  不能通过修改 Control.longitudinal.acceleration 直接测试不同制动力，因为底盘代码目前忽略了这个字段。

  ## 1. 安全条件

  测试前必须满足：

  - 封闭直线路段。
  - 前后至少各留 10 m。
  - 最高测试速度先限制为 0.1～0.3 m/s。
  - 急停按钮有效。
  - 一人操作终端，一人观察车辆。
  - 不启动 mission loop。
  - 不发布 goal。
  - 测试时关闭自动避障任务流程，避免其他节点争抢 external command。
  - 准备一个独立的持续零速命令终端。

  特别注意：不要使用单次 --once 发布非零速度。vehicle command gate 或底盘可能锁存最后一条指令。

  ## 6. 执行低速阶跃测试

  先在终端 3 按 Ctrl+C 停止零速 publisher。

  然后执行下面这个带自动归零的测试。第一轮只测 0.1 m/s：

  bash -c '
  set -e

  stop_vehicle()
  {
    timeout 3 ros2 topic pub -r 20 \
      /external/selected/control_cmd \
      autoware_control_msgs/msg/Control \
      "{lateral: {steering_tire_angle: 0.0}, longitudinal: {velocity: 0.0, acceleration: -1.0, is_defined_acceleration: true}}" \
      >/dev/null 2>&1 || true
  }

  trap stop_vehicle EXIT INT TERM

  echo "保持零速 3 秒"
  stop_vehicle

  echo "下发 0.1 m/s，持续 5 秒"
  timeout 5 ros2 topic pub -r 20 \
    /external/selected/control_cmd \
    autoware_control_msgs/msg/Control \
    "{lateral: {steering_tire_angle: 0.0}, longitudinal: {velocity: 0.1, acceleration: 0.2, is_defined_acceleration: true}}" \
    >/dev/null 2>&1 || true

  echo "自动下发零速"
  stop_vehicle

  trap - EXIT INT TERM
  echo "测试结束"
  '

  这个命令具有以下保护：

  - 非零速度只持续 5 秒。
  - 正常结束后自动连续发布 3 秒零速。
  - 按 Ctrl+C 也会尝试执行零速。
  - 转向角固定为 0。

  仍需保证物理急停可用，因为 shell、ROS 或网络完全失效时，软件 trap 不能代替急停。

  ## 7. 逐步增加速度

  确认 0.1 m/s 正常停车后，依次测试：

  0.2 m/s
  0.3 m/s

  例如第二档修改为：

  velocity: 0.2

  持续时间保持相同，避免同时改变多个变量。

  ## 9. 需要计算的延迟

  从 bag 中计算以下时间点：

  t0：/external/selected/control_cmd 发生阶跃
  t1：/control/command/control_cmd 发生阶跃
  t2：/can_driver/debug/control_cmd_rx 发生阶跃
  t3：/can_driver/debug/control_cmd_can 发生阶跃
  t4：/vehicle/status/velocity_status 开始明显变化
  t5：/localization/kinematic_state 速度开始明显变化

  对应延迟：

  gate 延迟       = t1 - t0
  ROS/CAN 接收延迟 = t2 - t1
  CAN 转换延迟     = t3 - t2
  底盘响应延迟     = t4 - t3
  定位链路延迟     = t5 - t4
  总响应延迟       = t5 - t0

  速度开始变化建议定义为：

  加速阶段：反馈速度首次超过 0.02 m/s
  停车阶段：反馈速度首次低于 0.02 m/s

  ## 10. 还要测停车距离

  零速指令开始时记录位置：

  P_stop_command

  车辆稳定停止后记录位置：

  P_final

  滑行距离：

  coast_distance = |P_final - P_stop_command|

  如果从 0.2 m/s 下发零速后：

  - 总延迟 0.2 秒；
  - 延迟期间车辆保持约 0.2 m/s；

  仅延迟部分就会产生：

  0.2 × 0.2 = 0.04 m

  即约 4 cm。再加底盘减速过程，很容易形成目前观察到的 3～13 cm 停车误差。

  ## 11. 测完后恢复 Autonomous

  先保证零速 publisher 正在运行且车辆静止，然后执行：

  ros2 service call \
    /api/operation_mode/change_to_autonomous \
    autoware_adapi_v1_msgs/srv/ChangeOperationMode "{}"

  确认：

  ros2 topic echo \
    /control/vehicle_cmd_gate/operation_mode \
    --once

  mode: 2
  is_autoware_control_enabled: true
