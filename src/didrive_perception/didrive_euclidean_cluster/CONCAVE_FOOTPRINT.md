# 聚类障碍物轮廓改进说明

## 背景

在厂房门洞附近，门框、墙壁和墙边物品可能被欧式聚类连接成一个长条目标。旧实现对整组点取二维凸包，会把点云之间的凹口也填为障碍物占位。2026-11-04 的 `141231_bag` 中，`lidar_rule/objects` 出现过长约 17–24 米的未知物体轮廓。

## 本次修改

聚类和目标数量保持原样；仅改变满足条件的长目标的 `Shape::POLYGON` 轮廓：

1. 对原始聚类点的 XY 坐标建立分辨率为 `footprint_resolution` 的占用栅格。
2. 用 `footprint_connection_radius` 扩张点占用，使相邻点连成轮廓。
3. 将占用裁剪到原凸包内，因此新轮廓不会超过原凸包的边界。
4. 提取单一外轮廓并简化顶点。仅当轮廓有效、顶点数不超过 200、面积比凸包至少减少 `footprint_min_area_reduction` 时采用。
5. 其余情况回退到原凸包，包括轮廓分成多个区域、过小或过大的栅格、以及面积收益不足的情况。不会因此丢弃聚类的一部分点或生成额外跟踪目标。

当前配置位于 `config/voxel_grid_based_euclidean_cluster.param.yaml`：

| 参数 | 当前值 | 含义 |
| --- | ---: | --- |
| `use_concave_footprint` | `true` | 启用长目标轮廓改进；节点默认值为 `false` |
| `footprint_resolution` | `0.1` 米 | 轮廓栅格精度 |
| `footprint_connection_radius` | `0.5` 米 | 点占用的连接半径 |
| `footprint_min_extent` | `6.0` 米 | 仅对跨度达到该值的目标尝试改进 |
| `footprint_min_area_reduction` | `0.15` | 至少减少 15% 的凸包面积才采用 |

## 验证与边界

`test/test_concave_footprint.cpp` 覆盖两个情形：长 U 形点云的开口不再被凸包填满；闭合的大型目标中心仍保持占用。测试直接调用实际的 `DetectedObjects` 输出路径。

已用 `141231_bag` 的门洞片段做双节点回放：一个节点使用旧凸包，一个启用新轮廓，两者订阅相同的 `/perception/obstacle_segmentation/pointcloud`，按消息时间戳比较跨度至少 10 米的目标。在可匹配的 265 帧中，256 帧的面积减少；这 256 帧的面积减少中位数约为 52.7%，最大约为 61.3%。这是**聚类输出轮廓面积**的对比，不等于车辆可通行净空增加相同比例，也未验证下游规划一定保留该凹口。

本方法**没有拆分已经连接的墙和物品**。如果点云连接半径使整个开口仍被占用，或者栅格形成多个独立轮廓而触发回退，输出仍可能是原凸包。内部空洞也不会从单个 ROS `Polygon` 中表达出来。`didrive_detected_object_validation` 的车道过滤阶段会对轮廓点另算凸包以检索候选车道；本次修改不改变该阶段的判定逻辑。

上线前应在原 bag 的门洞片段和包含大货车、行人、稀疏远距离点云的 bag 上同时比较：聚类数量、轮廓面积、门洞最小净空、目标跟踪连续性、规划结果和处理耗时。不能仅凭轮廓变小认定通行安全；实际可通行净空仍要结合原始点云、车体尺寸与定位误差确认。
